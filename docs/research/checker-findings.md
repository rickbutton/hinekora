# Checker findings from the probe and example crafts

Issues the checker itself showed while the research crafts were written, each with the
probe that reproduces it (`probes/`), separated into soundness, precision, naming and
language. "Precision" means a false positive: the game allows the step, the checker
cannot prove it. B11 was the one false negative found.

| #   | Kind      | Finding                                                                                                                                                                                                                                                                                                                                                                                                                     | Reproduce                                      |
| --- | --------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------- |
| B1  | precision | `until` reports "can never exit" when the exit predicate needs more than one iteration: it is tested after one body pass (`check.ts` `checkUntil`, "reachability first"). `until suffixCount <= 2 and prefixCount <= 2 { annul }` from a 3+3 item, three annuls to `prefixCount == 1 and suffixCount == 0`.                                                                                                                 | `t5.craft`, `self-fracture` first draft        |
| B2  | precision | The count domain stores `total` and `prefix` ranges and derives the suffix range, so a suffix-side fact cannot be kept unless the prefix count is pinned: after `until prefixCount <= 1 and suffixCount <= 2 { annul }` the state still shows 0–3 suffixes and a bench craft on a suffix is refused; `if suffixCount == 3 { … }` does not narrow. This is the "annul to make room" step of nearly every guide (R3, R6, R7). | `t8.craft`, `t8b.craft`, `essence-minion-wand` |
| B3  | naming    | A bench-only modifier cannot be named in a predicate: `has "suffixes cannot be changed"` and `has "can have up to 3 crafted modifiers"` are "Unknown mod", although the surface doc says a `beast metamod` result is narrowed by `if has "…"`.                                                                                                                                                                              | `t6.craft`, `t9.craft`                         |
| B4  | precision | (fixed) After `veiled exalt`, a `bench "maximum mana"` made the veiled modifier disappear (the next `unveil` says there is none); an `exalt` in the same place does not. The bench's replace-one-crafted-modifier path seems to remove the veiled placeholder as if it were crafted. If the game keeps the veiled modifier, this is a false positive on the unveil; either way the state is wrong.                          | `t15.craft` vs `t13.craft`                     |
| B5  | precision | `beast metamod` with every suffix filled does not collapse to "Suffixes Cannot Be Changed": a Harvest reforge afterwards shows 0–3 suffixes. Cannot be confirmed from the surface until B3 lets the result be named.                                                                                                                                                                                                        | `matron-metamod` draft                         |
| B6  | precision | (fixed) `harvest augment "physical"` on a +1 gems amulet with the prefix lock is refused ("every physical modifier may be blocked on some path") when the item came out of an imprint-and-regal loop, and accepted on the same item written directly (`t16`–`t18`).                                                                                                                                                         | `imprint-regal-amulet` draft                   |
| B7  | naming    | Word matching cannot name a hybrid ("fire and chaos resistance", the veiled "% life / % mana") because every query word must match; number-bearing wordings split one implicit into two names ("strike skills target 1" / "… 2"); a mod with one tier still needs `t1` in the item block; community names ("spell suppression", "chaos res", "ele res") do not resolve.                                                     | `06-veiled-unveil`, `02-prefixes-locked-scour` |
| B8  | naming    | Two tincture ids share the display name "Ashbark Tincture", so the base is ambiguous with no hint which id is the modern one. Fixed: same-named bases that agree on class, domain, tags and caps resolve to one.                                                                                                                                                                                                            | `18-tincture`                                  |
| D1  | data?     | `has "bleeding"` on a Divine Life Flask offered weapon mods as candidates, so the candidate narrowing to the base's pool fell through to the whole catalog; the correct flask suffix resolves when named in full.                                                                                                                                                                                                           | `10-flask`, `16-flask2`                        |
| B9  | precision | (fixed) A bench craft is refused for a group conflict inside `if not has "<mod>" { bench "<mod>" }`: the branch excludes one type, the bench checks the whole group, and other types of the group (hybrids, the bench's own row) stay possible. The refusal now names the group's modifiers the item may carry, so the guard can rule them out one by one; B12 is where that guard cannot be written.                       | `future/essence-minion-wand`                   |
| B10 | precision | (fixed) An inner `until` inside an outer loop is analysed from the outer loop's joined invariant, which admits states (down to an empty item) that no continuing path of the inner loop has, so its `annul` is refused as "may have none". A loop's body now runs only from the states where its exit predicate is false, and a refused step continues with the state its method would have left (`QUESTIONS.md` Q50).      | `future/metamod-harvest-loop`                  |
| B11 | soundness | (fixed) A declared `"random"` affix contributed no possible modifier type, so `has "maximum life"` on an item whose only affix was a random prefix was "impossible" and, worse, a bench craft of a group the random might carry was accepted. An anonymous affix is now every natural modifier of its side the item could roll (QUESTIONS.md Q49 for the crafted case).                                                     | `t26.craft`, `t32.craft`                       |
| B12 | naming    | (fixed, `has group`) The guard over a bench craft's group cannot be written when a member's name is ambiguous across the sides: on a wand "increased fire damage" is a caster prefix (the bench's group) and a suffix of its own group, and the clash message names it by that very label. Needs a side qualifier on `has`, or a group-level `has`.                                                                         | `future/essence-minion-wand`                   |
| B13 | precision | (fixed) A removal of crafted modifiers took any type with a bench row for a possibly crafted one, so after an unveil whose wording the bench also offers, replacing a crafted prefix metamod could cost the item a suffix; the state now carries the types a bench craft may have put on the item (`craftedTypes`), which is all the removal reaches, and the crafted count is bounded by those still possibly present.     | `veiled-unveil`                                |
| B14 | precision | (fixed) A random removal forgot every guaranteed modifier it could reach, so "the orb took the metamod or the life" followed by "the life is still there" left the metamod possibly present; the removal now keeps all but one of them and, when it could reach nothing else, knows one of them is gone.                                                                                                                    | `veiled-unveil`                                |
| L1  | language  | (fixed, `stop`) No way to end the craft on a dead path from inside a loop: `restart` re-enters the loop, so "if the life was removed, the item is bricked" (R6) cannot be written; the loop then carries the bricked state round and the next step is refused for it.                                                                                                                                                       | `veiled-unveil` draft                          |
| L2  | language  | (fixed, `has "<mod>" <cmp> <int>` and `divine`) `has` has no value threshold and there is no Divine Orb, so a guide's "Life ≥ 110" stop condition is only writable where it coincides with a tier boundary (methodology G6).                                                                                                                                                                                                | `09-value-predicate`                           |
| L3  | language  | No recombinator, Hinekora's Lock / Allflame choice, catalyst, quality, enchant or synthesised implicit (methodology G2–G5, G7–G9).                                                                                                                                                                                                                                                                                          | `08`, `13`, `14`, `15`                         |

Verdicts the checker got right where the first draft of a craft was wrong (worth keeping
as examples of the tool doing its job): an annul to open a prefix may take a suffix
instead (ring loop); a regal may land on either side; a `restart` after a lost life roll
carries the veiled modifier back to the loop head; a `prefixCount == 1` make-room loop
can strip the item bare; the abyss jewel "of Onslaught" has weight zero everywhere, so a
loop waiting for it never exits.
